# Статистика сыгранных игр

Исследование для `BL-005`, 22 сентября 2026 года. Этот документ не включает сбор данных: для внешней отправки событий нужно отдельное решение.

## Вывод

Собирать агрегированную статистику партий можно, но не силами одного GitHub Pages. Текущая игра — статические HTML, CSS и JavaScript, которые GitHub Actions публикует в GitHub Pages. GitHub прямо описывает Pages как сервис статического хостинга и не поддерживает серверные языки. Нужен внешний приёмник событий или готовый аналитический сервис.

Рекомендация для небольшого публичного прототипа: отдельный Cloudflare Worker с D1. Он позволит хранить точные события, считать воронку и выгружать CSV. В текущих лимитах бесплатного плана это 100 000 запросов Worker и 100 000 записанных строк D1 в день, а также 5 ГБ D1. Для текущего масштаба ожидаемая стоимость — 0 USD, пока не превышены бесплатные лимиты.

## Что можно собирать

Минимальный набор без постоянного идентификатора игрока:

- `game_started`: версия, персонаж, время старта;
- `battle_finished`: номер боя, противник, победа/поражение, число ходов, длительность;
- `reward_chosen`: карта или отказ, без состава всей колоды;
- `game_finished`: победа/поражение, достигнутый этап, общая длительность, версия.

Для связи событий одной партии достаточно случайного `adventure_id`, который создаётся заново для каждого приключения. Постоянный user ID, имя, email, точный IP в таблице и полные журналы ходов для первой версии не нужны.

## Варианты

| Вариант | Что даёт | Ограничения | Оценка стоимости |
| --- | --- | --- | --- |
| Только GitHub | График трафика репозитория: посетители, клоны, ссылающиеся сайты, популярный контент | Не видит игровые события; трафик доступен только за 14 дней и не заменяет статистику Pages-игры | 0 USD |
| Cloudflare Web Analytics | Посещения и быстродействие, без смены DNS; заявлено как privacy-first | Не поддерживает custom events, поэтому не ответит на вопросы о победах и этапах | 0 USD |
| Plausible | Готовая панель, custom events и свойства событий | Внешняя подписка; custom events учитываются в тарифном объёме; точную цену нужно сверить перед покупкой | Платная подписка |
| Cloudflare Worker + D1 | Точные игровые события, SQL, свой CSV/дашборд | Нужны отдельный Cloudflare-проект, схема, endpoint, CORS, валидация и защита от мусорных событий | 0 USD в малом масштабе; далее по тарифам Cloudflare |
| Cloudflare Worker + Analytics Engine | Большой поток аналитических точек и SQL API | Адаптивная выборка менее удобна для точного учёта малого числа партий; Cloudflare предупреждает о будущем введении billing | Сейчас 0 USD; цены объявлены заранее |
| Локальный экспорт JSON/CSV | Игрок сам скачивает обезличенный отчёт | Нет автоматической общей статистики; файлы нужно собирать вручную | 0 USD |

Supabase тоже подходит как приёмник: бесплатный план включает 500 000 вызовов Edge Functions и базу 500 МБ. Но бесплатный проект может быть приостановлен после недели бездействия, поэтому для редко посещаемой игры он менее удобен, чем Worker + D1.

## Предлагаемая схема

1. Игра на GitHub Pages создаёт маленькие события с `event_id`, `adventure_id`, `event`, `version`, временем и строго разрешёнными полями.
2. Отправка идёт в Worker через `navigator.sendBeacon`, с резервным `fetch(..., {keepalive: true})`. Ошибка аналитики никогда не блокирует игру.
3. Worker разрешает CORS только для `https://vadimlarkin.github.io`, ограничивает размер тела, валидирует схему, отбрасывает неизвестные поля и дубли по `event_id`, а также ограничивает частоту. CORS сам по себе не защищает от поддельных запросов.
4. D1 хранит сырые события ограниченный срок, например 90 дней; агрегаты по дню и версии можно хранить дольше.
5. Просмотр — через Cloudflare Dashboard, защищённый админский endpoint или периодическую выгрузку CSV. Секреты никогда не попадают в JavaScript GitHub Pages.

## Приватность и надёжность

- До включения внешней телеметрии нужно показать игроку краткое и понятное описание сбора, добавить отказ и отдельно проверить применимые требования о приватности и локализации данных.
- Не собирать имя, email, адрес, текстовый ввод, отпечаток браузера или постоянный идентификатор.
- Добавить флаг `analytics_enabled`; при отказе не отправлять ничего вообще.
- Не хранить секрет в игре: всё, что доставлено браузеру, можно прочитать.
- Включить дедупликацию, повтор с ограничением, локальную очередь и очистку старых недоставленных событий.

## Что потребуется для внедрения

- Cloudflare-аккаунт, Worker, D1 и их отдельный deployment;
- таблица событий, схема валидации, rate limit и правила CORS;
- модуль телеметрии в игре с opt-in/opt-out и очередью;
- короткая политиика приватности и проверка её требований;
- SQL-запросы для воронки: старт → первая победа → гибрид → финал, а также победы/поражения и длительность по версии.
